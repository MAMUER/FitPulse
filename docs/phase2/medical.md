# Medical

## 12. Wellness boundary

### 12.1 Контекст

FitPulse — wellness-платформа, не медицинское ПО. Для поддержания этого статуса требуется чёткое разграничение wellness и medical данных/функционала.

Документация: `docs/medical-registration.md`, `docs/medical-registration/minzdrav-checklist.md`.

### 12.2 Acceptance Criteria

- FitPulse остаётся wellness-платформой, не ставит диагнозы, не назначает лечение
- В UI присутствует disclaimer: "Это не медицинский совет. При заболеваниях consult врача"
- Все health endpoints (`/api/v1/health/*`) помечены как wellness-only
- Специальные категории ПДн (здоровье, менструальный цикл) требуют explicit consent
- Код не содержит интеграций с EHR/МИС без юридической экспертизы

---

## 13. Юридический статус: wellness, не медицинское ПО

### 13.1 Контекст

FitPulse обрабатывает биометрические и медицинские данные пользователей. Однако платформа **не является** медицинским ПО по определению Приказа Минздрава № 334н и ФЗ № 323, так как:

- не ставит диагнозы (classifier возвращает `illness` как состояние, а не диагноз);
- не назначает лечение или лекарства (планы носят рекомендательный характер);
- не ведёт медицинскую документацию;
- не поддерживает принятие врачебных решений;
- нет интеграций с EHR/МИС.

Документация: `docs/medical-registration.md`, `docs/medical-registration/minzdrav-checklist.md`.

### 13.2 Acceptance Criteria

- FitPulse официально классифицирован как wellness-платформа во всех compliance-документах
- Размещён disclaimer в интерфейсе: "Это не медицинский совет. При заболеваниях consult врача"
- Политики обновлены и отражают wellness-статус
- Пользователи видят статус wellness-сервиса в интерфейсе
- Юридическое заключение о не-необходимости регистрации в Росздравнадзоре документировано
