# FitPulse v11 — Передача задач бэкенду

## Статус фронтенда

- Фронтенд в одном файле: `FitPulse_FINAL_v11_RELEASE.html`
- Бэкенд **не изменялся**.
- Проверка JavaScript-синтаксиса: PASS.
- Текущая базовая линия фронтенда с предыдущего полного прогона: 1800/1800 PASS на v10.
- v11 содержит изменения для стабилизации релиза (доступность/focus, мобильный вьюпорт, экранирование пользовательских значений, метаданные релиза, исправления юридических страниц/календаря/иконок).

## Что нужно реализовать на бэкенде

### 1. Аутентификация

- POST логин
- POST регистрация
- Подтверждение email / кода
- Сброс пароля: запрос кода, проверка кода, установка нового пароля
- OAuth: Google и VK
- Обновление сессии/токена и выход
- Серверная валидация и rate limiting

### 2. Профиль пользователя / конфиденциальность

- GET/PATCH профиля
- Смена пароля
- Загрузка/хранение аватара
- Подключенные устройства
- 2FA: подключение, проверка и коды восстановления
- Удаление аккаунта
- Экспорт/удаление персональных данных по законным требованиям

### 3. Календарь

- CRUD событий
- Типы событий: тренировка, питание, восстановление, работа, учеба, заметка
- Обработка даты/времени и часовых поясов
- Повторяющиеся события, если требуется по продуктовой спецификации
- AI-генерация предложений по календарю

### 4. Питание

- Предпочтения в питании пользователя
- Планы питания по дню/неделе/месяцу
- CRUD блюд и альтернатив
- Расчеты питания из серверных данных
- Синхронизация с календарем

### 5. Тренировки

- Планы тренировок
- Библиотека упражнений
- Завершение тренировок/прогресс
- Пользовательские упражнения
- Метаданные видео и URL/CDN видеопродакшена

### 6. AI

- Аутентифицированный AI endpoint
- История диалогов
- Контекст питания/тренировок/календаря
- AI-действия в календаре
- Серверная безопасность/rate limits/логирование

### 7. Чат / социальные функции

- Поиск пользователей
- Запросы в друзья / связи
- Диалоги и сообщения
- Realtime транспорт (WebSocket/SSE)
- Статус прочтения, статус набора текста, если требуется
- Модерация/репорт/блокировка
- Стикеры/медиа

### 8. Устройства / интеграции со здоровьем

- Apple Health / Google Health Connect / интеграции с носимыми устройствами по договоренности
- Безопасное OAuth/привязка устройств
- Фоновая синхронизация
- Состояния разрешений/ошибок

### 9. Карты

- Production-провайдер геокодирования/карт
- CRUD пользовательских мест
- Серверные API-ключи / прокси, где уместно

## Точка интеграции фронтенда

В HTML уже содержится `BACKEND_CONFIG` и хелпер `backendRequest(path, options)`. Бэкенд должен предоставить стабильные REST/JSON endpoint'ы и возвращать HTTP 2xx для успешных запросов, 204 для успешных пустых ответов, а также структурированные JSON-ошибки при неудачах.

Рекомендуемая структура ошибки:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable message",
    "details": {}
  }
}
```

## Требования безопасности

- HTTPS только в продакшене
- HttpOnly + Secure + SameSite cookies предпочтительны для браузерных сессий
- CSRF-защита, если используется cookie-auth
- Строгий белый список CORS
- Серверная авторизация на каждом ресурсе
- Rate limiting для auth, reset, AI и chat endpoints
- Хеширование паролей современным алгоритмом
- Никогда не доверять клиентским флагам роли/прав
- Валидировать и санитизировать все пользовательские данные
- Не хранить секреты/API-ключи в HTML

## Важные демо-границы фронтенда

Гостевые/демо-данные intentionally локальные. Реальная персистентность, аутентификация, AI, realtime чат, карты, видеохостинг и интеграции устройств относятся к бэкенду/сервисам.

## Критерии приема релиза

Интеграция с бэкендом завершена, когда:

1. Все демо-fallback'и заменены реальными API-ответами, где применимо.
2. Жизненный цикл auth/session работает через refresh/reopen.
3. Удаление конфиденциальных данных/аккаунта выполняется на стороне сервера и является аудируемым.
4. AI/чат/календарь/питание/тренировочные данные сохраняются в рамках аккаунта.
5. Production-медиа/карты работают без разглашения приватных credentials.
6. Полный набор регрессионных тестов RU/EN × Светлая/Темная × Нормальный/Высокий контраст проходит с нулевым количеством JS-ошибок.
