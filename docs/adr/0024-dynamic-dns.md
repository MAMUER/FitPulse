# ADR 0024: Выбор динамического DNS для production

## Статус

Принято

## Контекст

Кластер k3s развёрнут на VPS с динамическим IP-адресом провайдера. Для доступа к сервисам через доменные имена требуется динамическое DNS, которое автоматически обновляет A-запись при смене IP.

Требования:

- автоматическое обновление DNS при смене IP;
- поддержка HTTPS через Let's Encrypt;
- минимальная стоимость;
- надёжность.

## Решение

Использовать DuckDNS как динамический DNS-провайдер:

- **DuckDNS**: бесплатный сервис динамического DNS с поддержкой Wildcard-записей.
- **cert-manager**: автоматическое получение Let's Encrypt сертификатов для `*.duckdns.org`.
- **Ingress NGINX**: единый ingress с TLS-termination и WAF (ModSecurity).

## Последствия

- **Плюсы**: бесплатно, простота интеграции, поддержка HTTPS.
- **Плюсы**: Wildcard-сертификаты позволяют использовать любые поддомены.
- **Нейтрально**: зависимость от внешнего сервиса DuckDNS; при отказе сервиса обновление DNS прекращается.
- **Риски**: при смене IP нужно дождаться TTL-обновления DNS (обычно < 60 секунд).

## Рассмотренные альтернативы

- **Cloudflare DNS**: мощный, но требует бизнес-аккаунт для API с SLA.
- **No-IP**: бесплатный, но требует подтверждения домена каждые 30 дней.
- **AWS Route53**: надёжный, но платный и избыточный для домашнего/VPS-хостинга.

## Реализация

- `configs/k8s/overlays/production/duckdns-external-secrets.yaml` — ExternalSecret для DuckDNS токена.
- `scripts/ci/update-duckdns.sh` — скрипт обновления IP.
- `docs/SECURITY.md` — документация по TLS и DNS.
