# ADR 0019: Единый агрегатор Open Wearables для интеграции с носимых устройств

## Статус

Принято

## Контекст

FitPulse требует надёжной интеграции с носимыми устройствами без использования прямых vendor-specific API. Архитектура должна поддерживать устройства из нескольких экосистем и нормализовать входные биометрические данные для последующих ML- и тренировочных сервисов.

## Решение

Использовать единый агрегатор Open Wearables:

1. **Open Wearables** выступает единым источником данных, агрегирующим данные из Apple Health, Garmin, Health Connect и других экосистем.
2. **Device Aggregator** (`cmd/device-aggregator/`) сохраняется как легковесный HTTP-relay для валидации HMAC-SHA256 подписи и форвардинга webhook в `biometric-service`.
3. **Прямые OAuth-роуты** удалены из кодовой базы.
4. **Хранение токенов** для прямых провайдеров не требуется.

## Последствия

- **Плюсы**: упрощение архитектуры, единая точка сохранения биометрики, снижение количества секретов, сокращение поверхности атаки.
- **Нейтрально**: `device-aggregator` продолжает жить как отдельный deployment, но его нагрузка снижена до minimum.
- **Риски**: при отказе Open Wearables интеграция теряется; требуется мониторинг доставки webhook.

## Реализация

- `cmd/device-aggregator/webhooks.go` — общий обработчик webhook для Open Wearables.
- `cmd/device-aggregator/main.go` — роутинг только `/api/v1/integrations/open-wearables/webhook`.
- `internal/repository/pgx/device_repository.go` — репозиторий устройств без OAuth-логики.
- K8s deployment оставлен без секретов `FITBIT_*`/`WITHINGS_*`.
