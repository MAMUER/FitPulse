# Чеклист для регистрации медицинского ПО в Росздравнадзоре

> **Статус FitPulse:** Wellness-платформа. Медицинское ПО по определению 152-ФЗ и Приказу 334н не является. Регистрация в Росздравнадзоре не требуется.
> Документация: `docs/medical-registration.md`.

## 0. Анализ текущего состояния FitPulse

### 0.1 Инвентаризация медицинских и wellness-данных

| Категория | Таблица / Эндпоинт | Тип данных | Медицинское ПО? |
| --- | --- | --- | --- |
| Учётная запись | `user_profiles` | wellness | Нет |
| Биометрические данные | `biometric_data` (`metric_type`: hr, spo2, temperature, blood_pressure_*) | wellness + medical-grade | Нет (wellness) |
| Состав тела | `user_body_composition` | wellness | Нет |
| Заболевания / состояния | `user_health_conditions` | медицинские adj. | Нет (wellness) |
| Противопоказания | `user_contraindications` | медицинские adj. | Нет (wellness) |
| Менструальный цикл | `user_menstrual_cycles`, `user_menstrual_symptoms`, `user_menstrual_moods` | медицинские adj. | Нет (wellness) |
| Планы тренировок | `training_plans` | wellness | Нет |
| Достижения | `achievements` | wellness | Нет |
| Устройства | `devices`, `device_tokens` | wellness | Нет |

### 0.2 Функционал, bordering medical

| Функционал | Реализация | Риск реклассификации? |
| --- | --- | --- |
| Классификация состояния | `cmd/classifier/main.go` — rule-based (`illness`, `overtraining`, `normal`) | Нет — нет диагноза, нет назначения лечения |
| Генерация планов | `cmd/ml_generator/main.py` — DDPM с fallback на rule-based | Нет — рекомендательный, не назначает лечение |
| Интеграции с wearables | Open Wearables (Apple Health, Garmin, Health Connect) | Нет — агрегация, не EHR |
| Хранение заболеваний | `user_health_conditions` — user-reported, не диагностика | Нет — нет врачебной верификации |

### 0.3 Границы wellness vs medical

| Критерий | FitPulse | Медицинское ПО? |
| --- | --- | --- |
| Диагностика заболеваний | ❌ Нет | Да |
| Назначение лекарств | ❌ Нет | Да |
| Врачебное сопровождение | ❌ Нет | Да |
| Ведение медицинской документации | ❌ Нет | Да |
| Обработка биометрических данных | ✅ Да | Частично |
| Генерация планов на основе состояния | ✅ Да (rule-based) | Нет |
| Интеграция с медицинскими сервисами | 🔄 Roadmap (Phase 3+) | Да (при реализации) |

**Вывод:** FitPulse — wellness-платформа. Медицинское ПО не является. Регистрация в Росздравнадзоре не требуется.

### 0.4 Compliance-риски

| Риск | Вероятность | Влияние | Митигация |
| --- | --- | --- | --- |
| Росздравнадзор классифицирует как медицинское ПО | Низкая | Среднее | Юридическая экспертиза, Terms of Use с disclaimer |
| GDPR special categories (здоровье) | Средняя | Высокое | Explicit consent, DPIA, pgsodium encryption |
| Утечка медицинских данных | Средняя | Высокое | Шифрование, audit log, RBAC |

### 0.5 Юридическое заключение

FitPulse обрабатывает специальные категории ПДн (здоровье, менструальный цикл) по GDPR Art. 9 и 152-ФЗ. Однако:

1. Нет диагностики, лечения, реабилитации
2. Нет поддержки принятия врачебных решений
3. Нет интеграции с EHR/МИС
4. Все планы носят рекомендательный характер

**Заключение:** Медицинское ПО по Приказу 334н и ФЗ № 323 **не является**. Регистрация в Росздравнадзоре **не требуется**. Требуется compliance по 152-ФЗ (special categories) и GDPR Art. 9 (explicit consent).

## X. Техническое разграничение wellness/medical данных

### X.1 Цель

Предотвратить реклассификацию FitPulse как медицинского ПО за счёт чёткого разделения wellness и medical данных в коде, документации и UI.

### X.2 Правила разграничения

| Тип данных | Примеры | Обработка | Медицинское ПО? |
| --- | --- | --- | --- |
| Wellness | Шаги, калории, тренировки, достижения | Стандартная обработка | Нет |
| Medical-adjacent | Заболевания, менструальный цикл, противопоказания | Требует explicit consent | Нет (wellness) |
| Medical-grade биометрики | Температура, кровяное давление, SpO2, HRV | Требует explicit consent | Нет (wellness) |
| Медицинские данные | Диагнозы, назначения, результаты анализов | **Не обрабатываем** | Да |

### X.3 Implementation guidelines

1. **Код:** Не добавлять диагностику, назначение лечения, интеграцию с EHR без юридической экспертизы
2. **API:** Все health endpoints (`/api/v1/health/*`) — wellness-only, не диагностика
3. **UI:** Disclaimer "Это не медицинский совет" на всех экранах с medical-adjacent данными
4. **Документация:** Чётко указывать, что FitPulse — wellness-платформа
5. **Consent:** Explicit consent для специальных категорий ПДн при регистрации

### X.4 Запрещённый функционал (требует медицинской регистрации)

- ❌ Диагностика заболеваний по симптомам
- ❌ Назначение лекарств или процедур
- ❌ Врачебные заключения или справки
- ❌ Интеграция с EHR/МИС без регистрации
- ❌ Передача данных врачам без явного согласия
