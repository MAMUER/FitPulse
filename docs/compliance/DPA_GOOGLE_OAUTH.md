# Data Processing Agreement (DPA) — Google OAuth 2.0

> **Назначение:** Настоящий DPA регулирует обработку персональных данных (ПДн) в рамках интеграции FitPulse с Google OAuth 2.0. Документ составлен в соответствии с требованиями GDPR (ст. 28) и 152-ФЗ, учитывает трансграничную передачу ПДн в США и обязанности сторон как контроллера и процессора.

## 2. Предмет обработки

FitPulse использует Google OAuth 2.0 для аутентификации пользователей. В рамках интеграции Google предоставляет FitPulse следующие ПДн из ID-токена:

| Категория ПДн | Пример | Специальная категория? |
| --- | --- | --- |
| Идентификатор аккаунта Google (`sub`) | Уникальный идентификатор пользователя Google | Нет |
| Email | Адрес электронной почты пользователя | Нет |
| Имя | Имя пользователя из профиля Google | Нет |
| Фото профиля | URL аватара пользователя | Нет |

**Важно:** FitPulse не запрашивает и не получает доступ к другим данным Google (календарь, контакты, Drive и т.д.). Scopes: `openid`, `profile`, `email`.

## 3. Правовое основание обработки

- **GDPR:** Согласие субъекта (Art. 6(1)(a) + Art. 9(2)(a) для специальных категорий, если применимо).
- **152-ФЗ:** Согласие субъекта на обработку ПДн (ст. 9).
- **Google Terms of Service:** Политика конфиденциальности Google (`https://policies.google.com/privacy`).

## 4. Обязанности контроллера (FitPulse)

1. **Минимизация данных:** FitPulse получает только те данные, которые необходимы для аутентификации (`sub`, `email`, `name`, `picture`). Дополнительные scopes не запрашиваются.
2. **Информирование субъекта:** Пользователь информируется о том, что при использовании Google Sign-In его email, имя и фото передаются в Google и обратно в FitPulse. Информация содержится в Политике конфиденциальности (`/privacy`).
3. **Согласие:** Пользователь явно соглашается на обработку ПДн через Google OAuth, принимая Политику конфиденциальности при регистрации.
4. **Защита данных:** Полученные ПДн шифруются в БД через pgsodium (aegis256) и защищаются TLS 1.3 in transit.
5. **Права субъектов:** FitPulse обеспечивает реализацию прав субъектов (доступ, исправление, удаление, портируемость) через API endpoints.
6. **Transparency:** FitPulse информирует пользователя о трансгранильной передаче ПДн в США (см. раздел 7).

## 5. Обязанности процессора (Google LLC)

1. **Обработка по инструкциям:** Google обрабатывает ПДн исключительно в соответствии с инструкциями FitPulse (через OAuth 2.0 flow) и своей Политикой конфиденциальности.
2. **Конфиденциальность:** Google обеспечивает конфиденциальность ПДн в соответствии с своими обязательствами как процессора.
3. **Меры защиты:** Google применяет отраслевые стандарты безопасности для защиты ПДн.
4. **Субпроцессоры:** Google может использовать субпроцессоров в соответствии со своей Политикой конфиденциальности.
5. **Удаление данных:** Google удаляет ПДн по запросу FitPulse или по запросу субъекта (через интерфейс Google Account).

## 6. Трансграничная передача ПДн

### 6.1 Направление передачи

- **Из РФ в США:** При использовании Google OAuth 2.0 ПДн пользователя (email, имя, фото) передаются из РФ в серверы Google LLC в США.
- **Механизм:** Трансграничная передача осуществляется через стандартный OAuth 2.0 flow (HTTPS/TLS 1.3).

### 6.2 Правовое основание

- **GDPR Art. 49(1)(a):** Явное согласие субъекта на трансграничную передачу.
- **152-ФЗ:** Согласие субъекта на обработку ПДн, включая трансгранильную передачу (ст. 12).

### 6.3 Уровень защиты в стране получателя

- **США:** Не имеют решения о «adequate protection» от Европейской комиссии. Однако Google применяет Standard Contractual Clauses (SCC) для трансграничных передач.
- **Меры FitPulse:**
  - FitPulse заключает DPA с Google (настоящий документ).
  - Google применяет SCC для защиты ПДн при трансграничной передаче.
  - FitPulse информирует пользователей о трансгранильной передаче в Политике конфиденциальности.

### 6.4 Дополнительные гарантии

- FitPulse не передаёт ПДн в Google, кроме случаев аутентификации через OAuth 2.0.
- FitPulse не использует Google для аналитики или рекламы на основе ПДн пользователей.
- Пользователь может отказаться от Google OAuth и использовать email/пароль для аутентификации.

## 7. Меры защиты ПДн при интеграции

| Мера | Описание |
| --- | --- |
| Шифрование in transit | TLS 1.3 для всех вызовов Google OAuth endpoints |
| Шифрование at rest | pgsodium (aegis256) для хранения email, имени, фото в БД |
| Минимизация данных | Запрашиваются только scopes: `openid`, `profile`, `email` |
| Срок хранения | Данные хранятся до удаления аккаунта |
| Удаление данных | При удалении аккаунта все ПДн, полученные через Google OAuth, удаляются из БД |
| Логирование | Все операции с ПДн через Google OAuth логируются в audit log |
| Мониторинг | Обнаружение аномалий в OAuth flow (подозрительные redirects, excessive token requests) |

## 8. Срок действия и пересмотр

- **Срок действия:** Настоящий DPA действует с момента утверждения и до момента прекращения использования Google OAuth 2.0 FitPulse.
- **Пересмотр:** DPA пересматривается при изменении:
  - Google Privacy Policy или Terms of Service
  - Требований законодательства РФ или GDPR
  - Архитектуры интеграции (добавление новых scopes)
- **Уведомление:** Изменения в DPA публикуются в репозитории и в Политике конфиденциальности.
